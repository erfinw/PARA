# Obsidian Workflow

## Core Loop

**Capture → Clarify → Classify → Connect → Act → Review**

The goal is reliable thinking and retrieval, not perfect filing.

## 1. Capture

Put raw thoughts, notes, links, meeting notes, ideas, and observations into `00_Inbox`.

Do not interrupt capture to decide where something belongs.

### Capture rule

One thought per note when the thought is likely to be useful later.

## 2. Clarify

For each Inbox item, ask:

- What is this?
- Why might it matter?
- Is there an action?
- Is it connected to an existing Project, Area, or Resource?

## 3. Classify

Use PARA:

- **Project** — has a desired outcome and finish line.
- **Area** — ongoing responsibility with no finish line.
- **Resource** — reusable reference or knowledge.
- **Archive** — inactive material worth keeping.

If an idea is interesting but not committed, put it in `01_Projects/_Someday-Maybe`.

## 4. Connect

Prefer links to duplicate notes.

Examples:

- `[[TravelUp Validation]]`
- `[[Digital Marketing]]`
- `[[Business]]`
- `[[Strategic Thinking]]`

When a new note materially relates to an existing note, add a wikilink.

## 5. Act

Every active Project should have:

- Outcome
- Current status
- Next action
- Success measure
- Key decisions
- Relevant links

A Project without a next action is probably not active.

## 6. Review

### Daily

- Empty or reduce Inbox.
- Capture important decisions and lessons.
- Confirm the next actions for active Projects.

### Weekly

- Review every active Project.
- Review Areas for neglected responsibilities.
- Process Inbox.
- Move completed work to Archives.
- Promote or demote projects based on current priorities.
- Identify one to three strategic priorities for the coming week.

### Monthly

- Review goals and capability development.
- Look for recurring themes.
- Identify knowledge gaps.
- Review business portfolio allocation.
- Review whether current commitments still support the North Star.

## AI Operating Rule

AI should assist classification, summarization, linking, retrieval, and review. The human remains the final authority for commitments, sensitive information, and major decisions.

## GitHub Rule

GitHub is the versioned source of truth for the Markdown knowledge base. Avoid storing passwords, API keys, access tokens, confidential employer data, sensitive personal data, or other secrets in the repository.
